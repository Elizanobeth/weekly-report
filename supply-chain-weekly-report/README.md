# 供应链信息化团队周报

这是第一版本地汇报应用。当前使用模拟数据，先验证三表关系、周次过滤、按成员汇报和摘要展示；WPS 开放接口将在取得测试凭证后接入。

## 当前能力

- 使用 KPI 表、事项台账、周报记录表三组模拟数据；
- 支持 `2026-W36`、`2026-W37` 两个周次切换；
- 只显示所选周次存在任务进展记录的事项；
- 按责任人一人一页展示，不合并同项目下不同成员的任务；
- 展示本周进展、存在问题、需要帮助和下周计划；
- 展示完成比例、当周计划比例及进度偏差；
- 团队摘要的每一项可以跳转到来源任务；
- 支持在本次本地运行期间生成“模拟最终版”；
- 保留 WPS 只读和非生产读写能力检查脚本。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm start
```

浏览器打开：

```text
http://127.0.0.1:4173
```

页面上会持续显示“模拟数据”提示，避免被误认为真实周报。

## 模拟数据

- `mock/kpi.json`：保持现有 KPI 字段含义的项目任务；
- `mock/work-items.json`：KPI 项目、非 KPI 需求和临时任务统一台账；
- `mock/weekly-records.json`：按周纵向保存的任务进展与团队摘要。

模拟数据包含以下验收场景：

- 同一项目由两名成员承担不同任务；
- KPI 与非 KPI 事项同时汇报；
- 正常、有风险、需协同和已完成状态；
- 有上周记录但本周没有记录的事项，本周页面完全隐藏；
- 历史周次仍能还原当周任务与进度。


## WPS 能力检查

真实接入前请使用非生产 WPS 多维表格。配置方法见 `.env.example`，凭证只能通过本机环境变量提供，禁止提交到 Git。

只读检查：

```bash
npm run check:wps
```

写入检查需要同时满足命令参数和环境变量的双重确认：

```bash
WPS_ALLOW_WRITE=YES WPS_TEST_TEXT_FIELD=探针字段 npm run check:wps -- --write
```
